# 开发与验证执行规则

本项目由当前会话完成开发、自检、整改和交接。用户于2026-10-28授权取消开发AI/独立审计AI分工，允许当前会话按明确目录和职责使用子代理；不自动启动固定开发B/独立审计流程，不要求设计预审、独立审计PASS、逐轮四件套或审计流程skills。自检报告明确标为开发者验证。

## 执行顺序

1. 从stage-plan读取实际进度，核对现有代码、前置报告和未提交改动；保留既有代码、正式测试与历史证据。
2. 按依赖完成实现和必要回归。同一会话兼任集成负责人，统一维护契约真源、生成物、根构建和状态；生成物仍通过正式生成器维护。
3. 对历史审计中的具体缺陷逐项核对，已修项用代码及正式测试证明，未修阻塞项继续整改。取消审计流程不等于取消已知产品缺陷。
4. 收尾检查临时残留、同步当前文档，运行普通Debug构建和全量CTest；每卡收尾运行ASan/UBSan，涉及线程/共享状态/锁时运行TSan。Linux证据仅用ssh locker-vm的VMware Ubuntu，不用WSL。
5. summary≤10KB、handoff≤8KB，记录命令、退出码、失败路径、未验证项、下一卡和实际耗时。满足卡验收才标DONE，阶段集成验证满足才标PASS；每完成一张卡本地提交，不push。
