# 具备独立监护与异常恢复能力的实验室工具借还柜

执行架构、业务状态与接口以[阶段 0 设计](stages/stage-00-architecture.md)及[契约入口](../contracts/README.md)为当前依据。本文保留产品范围、硬件与成本约束；[阶段 1 任务卡](stages/stage-01-task-cards.md)规定下一阶段实际开发顺序。

## 1. 产品与交付边界

面向实验室共享万用表等工具，首版为一个柜格、一件固定工具。完成真实的刷卡、开门、取物、关门、确认、归还流程，并用现有的故障记录与监护方案处理异常中断。

Android 手机、RK3568 和路由器位于同一局域网。Android App 与柜体触摸屏使用同一套业务状态；借用人确认操作，物理检测冲突交管理员核验。管理员可维护用户权限、工具状态并查看异常记录。

在位传感器只确认固定槽位是否有物体，不识别工具真伪。首版不宣称防盗保险柜、工业级门禁或高可靠资产身份识别。普通 RC522 卡 UID 只能作为原型身份标识；手机操作仍须服务端鉴权，到柜前确认后才执行开锁。

## 2. 系统架构

```text
Android App -- HTTPS / WebSocket -- RK3568 业务服务 -- UART/DMA -- STM32F407
                                  |                          |-- RC522 读卡器
                                  |                          |-- 电控锁与驱动保护
                                  |                          |-- 柜门门磁、工具在位开关
                                  |                          |-- SPI Flash 事件日志
                                  |                          |-- 主机供电 ADC 检测
                                  |                          `-- 独立于主机支路的供电
                                  |-- SQLite
                                  `-- LVGL 触摸界面
```

### STM32F407

- 使用用户已提供的HAL V1.8.5与FreeRTOS。通信、柜格控制/监护、Flash 存储通过队列交接；中断不执行擦写或业务数据库操作。
- UART DMA 负责指令和状态；报文包含版本、长度、操作 ID、序号与 CRC。重复指令不能重复开锁。
- RC522 和 Flash 可共享 SPI 总线、使用独立片选；共享总线需要统一仲裁，Flash 长操作不能阻塞柜门事件处理。
- 开锁采用短脉冲；GPIO 上电默认不驱动锁，限制最长通电时间，避免线圈长时间发热。
- 门磁确认开门/关门，工具槽微动开关确认在位/离位。没有独立锁舌反馈时，只能报告“未检测到开门”，不能把它直接判为锁损坏。
- SPI Flash 保存物理事件、监护事件、操作 ID、MCU 启动编号与事件序号，支持日志容量上限、提交校验和补取去重；复用 littlefs，不自行开发文件系统。
- 监测 Linux 心跳与界面事件循环进度；Linux 尚能响应时请求恢复界面，限制恢复次数，设置启动宽限期。
- MCU 独立看门狗根据关键任务进展喂狗。日志队列溢出、Flash 故障和传感器异常必须可见。

### RK3568

- 使用 C、CivetWeb、SQLite、cJSON 构建轻量业务服务，按实际用户态 ABI 交叉编译。资料中的 ARM32 工具链与 ARM64 平台描述需要通过真机 `uname`、`file` 和工具链验证后统一，不能直接照抄旧 CMake 路径。
- 业务服务拥有借还状态和数据库写入权。LVGL 与 Android 都通过统一业务接口提交操作，不能各自直接修改借还记录。
- 业务服务、LVGL 界面、独立 supervisor 分进程；首版只自动恢复 LVGL，不自动恢复业务服务，不重放开锁命令。业务服务人工重启后先核对；内核失联时 MCU 只记录与告警，不自动断电或硬复位主机。
- MCU 重连后先补取事件、核对当前门/物品状态，再开放新的借还操作。故障原因保留“事实、推测、未知”的边界。
- 正常运行时同步主机时间与 MCU 单调时间，保留同步点和启动编号；失联期间的时间不伪装成精确绝对时间。

### Android App

- 使用 Flutter，交付可安装的 Android APK。只验收 Android，不包含 iOS、应用商店上架、云端和蓝牙接入。
- 页面包含设备连接/登录、工具列表、当前操作、我的借用、历史记录、管理员权限与异常处理。
- HTTPS 使用明确的设备证书配对，禁止接受任意证书；会话保存于 Android 安全存储。
- 网络中断后显示状态过期，离线不能提交开锁；重连重新查询状态，不缓存并重放执行指令。
- WebSocket 推送当前操作与异常，首版不承诺 App 被系统结束后仍有后台推送。

I²C、CAN 均未禁止。首版没有必须接入的对应器件，不为接口数量额外购买模块。

## 3. 借还与异常规则

- 每个柜格同一时间只有一个有效操作。手机申请后，到柜前通过触摸屏或绑定卡片确认。
- 借出完成需要本人确认、柜门关闭、物品由在位变为离位；归还完成需要本人确认、柜门关闭、物品由离位变为在位。
- 如果手机确认和物理状态冲突，或已经取物但操作中断，则进入待核验；不能直接把工具重新标为可借。
- 请求接受、指令发出、门已打开、物品状态变化、借还完成分别记录。没有传感器证据的步骤不能标成完成。
- MCU 记录动作意图和执行事件；重启后的不确定操作先核对实物，不能自动再次执行开锁。
- 管理员的核验/更正保留原因和记录，不能无痕覆盖原始物理事件。
- 主机心跳消失只能证明主机或通信失联；供电变化作为独立证据，不能单凭串口失联断言内核死机。

## 4. 供电与结构

- RK3568 使用匹配其铭牌电压、极性、插头及负载能力的电源。不能把“常见 12V”当成实物已确认。
- MCU 使用独立的 5V 适配器供电，具体入口遵守开发板说明。独立是指不随被测主机支路一起断开；没有电池或 UPS 时，不承诺整个场所停电后继续运行。
- 柜锁用匹配的 12V 电源与 MOS 驱动；锁电流不能走开发板 3.3V、GPIO 或杜邦信号线。加入续流二极管、保险保护与去耦。
- UART 两侧电平和掉电反灌必须验证；计划预留双侧供电的串口信号隔离/断电保护器件。普通电平转换板不能自动视为具备掉电保护。
- ADC 分压按实际主机输入电压设计，低压检测与串口、电源线共同验证；不测市电，不宣称捕获高频瞬态掉电。
- 柜体采用可加工旧柜格/木质翻盖箱，工具放在固定托架。先量实物，再决定箱体内尺寸和锁扣位置。保留后侧人工维护入口。
- F407、RK3568 和屏幕可安装在柜体外侧已有支架上，首版不要求定制一体化外壳；不可省略电子模块绝缘固定。

## 5. 开发与 AI 交接顺序

1. 核对板型、电源、可用引脚、Flash、下载器、网络与柜体尺寸；按材料清单核算下单总价。
2. 固定借还状态、串口协议和 `/api/v1` 接口，建立清楚标记的模拟设备。
3. AI 开发 Flutter 页面和终端服务；先验证权限、并发、操作 ID 去重与重连。
4. 接入一个真实柜格，跑通读卡、锁、门磁、工具在位及一次完整借还。
5. 接入独立记录、供电检测、界面恢复、限次恢复与历史补取；完成异常试验。
6. 核对真实成本，更新接线、部署、协议、测试与已知限制；清理临时代码后执行检查。

2–3 周是首轮开发窗口，不承诺 App、机械安装和全部故障试验都在窗口内完成。未真机验证的功能只能标为待验证，不能用模拟结果替代。

## 6. 验收

- 一次真实借出、归还、只开门不取物、工具取出但未确认、归还状态冲突。
- 普通用户越权、两个用户争同一柜格、重复点击、响应丢失后重试不重复开锁。
- 手机退出/断网、UART 断开、LVGL 暂停、Linux 监护退出，恢复后物理状态与记录可核对。
- 主机支路断电时 MCU 仍能记录，主机恢复后补取不重复；MCU 写入期间重启后已提交记录可恢复。
- 恢复次数上限有效、启动宽限期有效、MCU 关键任务异常时看门狗行为可验证。
- 测量开锁通电时长、检测/恢复耗时、事件缺失、Flash/RAM、队列峰值和连续运行误报，报告实测条件，不预填漂亮数字。

## 7. 成本与当前实现依据

- 物料以[当前材料清单](材料清单与搜索比价-2026-10-20.md)和selected-bom为准，包含用户替换的器件与补件。原材料输入已归档，不继续执行板载DAP/VCP、固定NO极性或10k/22k分压的旧说法。
- 配件、运费和机动上限200元，按用户新清单F407板单独预算；保留两备件的候选/预留合计197.94元，不买备用锁分支176.04元。这不是结算价，不保证跨店运费/规格差价已覆盖。
- 候选天空星高配有板载Flash，但外接SWD、日志适配器与蜂鸣器不能默认取消；原配RK电源和现有工具复用，仍需记录实际参数。
- STM32固定HAL；本地STM32F4xx_HAL_Code的HAL V1.8.5可作为基线，原包不改。当前以架构/接口设计为主，不继续下载或配置工具；缺少的FreeRTOS/littlefs在阶段2按任务卡准备。
- [材料与HAL影响](hardware/材料变更影响与HAL边界.md)规定BSP/profile适配，公开HTTP与UART v1保留。引脚、极性、ADC与安全截止未验证前不驱动真锁。
- 首版纸箱只作桌面功能样机，锁/开关须刚性定位，不作为防盗结构；换硬柜后重新验收安装。
- 预算不包含云服务、域名、SIM、蓝牙、CAN、额外屏幕或第二柜格；不隐瞒条件补购，不用删保护电路满足金额上限。

## 8. 复用来源

- [FreeRTOS](https://github.com/FreeRTOS/FreeRTOS-Kernel)：任务与队列。
- [STM32CubeF4](https://github.com/STMicroelectronics/STM32CubeF4)：HAL 与外设例程，逐组件保留许可。
- [CivetWeb](https://github.com/civetweb/civetweb)：MIT，复用 HTTP/HTTPS/WebSocket 服务。
- [SQLite](https://www.sqlite.org/whentouse.html)：本地嵌入式数据库，不把数据库文件共享给手机。
- [littlefs](https://github.com/littlefs-project/littlefs)：BSD-3-Clause，复用 Flash 文件存储与恢复机制。
- [OpenEMC](https://github.com/surban/openemc)、[watchdogd](https://github.com/troglobit/watchdogd)：借鉴主机监督和事件留存思路；不整套移植 OpenEMC。
- [智能柜参考](https://github.com/meehhmett/smart_locker_system)：普通读卡开柜已有公开实现；本项目重点是物理状态核对与异常恢复，不把常见功能称为独创。
