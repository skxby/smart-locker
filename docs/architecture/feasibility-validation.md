## 3. 时间戳/硬截止的技术修正

MONOTONIC只说明时钟，EOF/SOE说明采样来源，两者必须分别验证。只有SOE或可证明的“原时间戳到曝光开始”上界，才能推出请求后的新曝光；手动曝光读回也不能覆盖相机内部缓冲/传输延迟。

captured_mono_ms定义为曝光开始的保守下界。SOE可直接使用；EOF/驱动估计时间需要在实际profile记录端到端上界B及验证证据，取timestamp-B，验证它晚于issued_mono_ms且到Core年龄不超2秒。未知B/来源不明/未来时间不具备REQUIRED资格。原始timestamp/flags/B存本机正式采集日志，profile哈希绑定结果；不增加MCU消息。streamoff/on或序号递增本身不代替该证明。

锁截止由选定TIMx_CHy实际复用管脚驱动MOS输入，停止输出的定时器硬件决定关闭；GPIO拉高+定时中断拉低不合格。先以假负载测启动/复位/调度阻塞/时钟及外部驱动延迟，再测线圈实际波形。profile没有确认到该管脚和负载路径前，不标硬截止已具备。

## 4. 接口验证与实施门槛

当前三项检查覆盖生成物/引用/样例、45卡DAG/目录、24公开/80C/28业务监督RPC/3视觉消息/11UART归属、过期/实例/跨操作证据负例。已通过部分是设计一致性，不是HTTP请求、C编译、UART DMA或NPU实际运行。

后续必须按卡补：S1-07真实HTTPS/IPC/模拟字节链；S2-05锁实际波形；S2-08真实Journal/借还；S2-11相机与曝光新鲜度；S2-12/15 RKNN一致性/柜内混淆/错还与故障；S2-16完整门禁；S3双端；S4故障恢复；S5现场连续运行。任一关键项失败保留证据并返回责任卡，不能把NOT_RUN改PASS。

该样机可识别类别错放并辅助人工核验，不能证明同类实物身份/数量/防伪；普通卡UID不等于高安全认证，纸箱不是防盗结构。若目标变成无人值守商用资产柜，现有证据与结构不能据此直接宣称达标。

## 5. 一手依据

- [Linux V4L2 buffers](https://docs.kernel.org/userspace-api/media/v4l/buffer.html)：时间来源和时钟由不同flags描述，不能只查MONOTONIC。
- [ST HAL定时器实现](https://github.com/STMicroelectronics/stm32f4xx-hal-driver/blob/master/Src/stm32f4xx_hal_tim.c)：复用官方HAL/定时器模式，硬输出还须验证BSP与线路。
- [ADuM1201官方资料](https://www.analog.com/en/products/adum1201.html)：两侧电源/逻辑范围需与真实IO一致。
- [RKNN官方MobileNet实现](https://github.com/airockchip/rknn_model_zoo/blob/main/examples/mobilenet/cpp/rknpu2/mobilenet.cc)：可借鉴加载/查询/推理/释放，不能当作自训v11已兼容的测试结论。
