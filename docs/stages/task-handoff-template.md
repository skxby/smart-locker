# 单卡开发与交接模板

完整步骤及全部45卡的180份指令见[AI开发执行手册](../AI开发执行手册.md)或[单卡索引](../ai-prompts/README.md)，每卡已填开发/审计/整改/交接，无需自己替换卡号。本文件保留通用格式。

用于以后明确开始某张开发卡。当前只有设计，不创建虚假开发报告。

## 给执行 AI 的提示词

```text
只执行 %REPO% 中的 <卡ID，例如S1-01>。
先读 AGENTS.md、README.md、docs/stages/README.md、config/development/stage-plan.json，
再读该卡及它引用的规格，核对当前契约版本和前置卡真实证据。
只改分配目录与相关正式测试/文档，不执行后续卡，不增加范围。
先报告本卡目标、接口、路径、验收，再开发；较大实现先查官方/GitHub复用。
环境不支持如实记未运行；真机要求不能由模拟/静态checker替代。
接口冲突提交变更请求，可继续独立部分，不静默新增API或修改验收。
完成时同步文档/状态，清理本轮明确临时残留，跑必要检查，
在docs/evidence/stage-XX/<卡ID>/summary.md记录证据，更新stage-plan并停止交接。
没有要求commit/push，不创建提交或推送。
```

## 每卡报告

| 字段 | 内容 |
|---|---|
| card / contract | 卡ID、契约版本、源码/制品指纹；未建Git时用SHA-256 |
| prerequisites | 前置报告链接和结果，不只写“应该完成” |
| scope | 修改文件、实现函数/API/消息，越界项应为无 |
| reuse | 来源、锁定版本/提交、许可与适配决定 |
| validation | 环境、完整命令/退出码、PASS/FAIL/NOT_RUN、正式日志/fixture |
| behavior | 成功与关键错误/超时/副作用次数、实测范围 |
| docs / residue | 当前文档同步；临时残留处理/不确定项 |
| decision | DONE/BLOCKED/IN_PROGRESS、原因、下一卡；关键验收未运行不可DONE |

## 共享接口变更请求

```text
CR-ID / 提出卡 / 当前契约版本
冲突：来源文件/字段/函数，调用为何不能成立
影响：生产者/消费者/持久化/重启兼容/API/测试
建议：最小修正、复用依据，有无新增预算/范围
依赖：等待部分、可继续部分
结论：契约负责人统一改真源/生成物/文档/样例/校验，记录版本后继续
```

不要把缺口变成各模块分别实现的TODO。负责人可在授权设计范围内统一处理常规修正，不额外增加内部修改审批流程。
